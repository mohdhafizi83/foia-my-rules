# Security Policy

## Data provenance

Every rules file in this repo was transcribed **manually from official
Malaysian government gazettes** and cross-checked against the published text:

| File | Source | Verification |
|---|---|---|
| `rules/my-penang-foi-2010.json` | Enakmen Kebebasan Maklumat Pulau Pinang 2010 (Enakmen 16), warta rasmi Jil. 56 Tambahan No. 1, 2 Feb 2012 | Fully verified against the official gazette |
| `rules/my-selangor-foi-2011.json` | Enakmen FOI Selangor 2011 | Section structure (22 sections) verified; full text pending gazette confirmation |
| `rules.json` | Combined index | Derived from the two files above |

Each rule carries a `url` field pointing at its original source so any
statement can be independently re-checked. This repo is a **structural
reference, not legal advice** — always consult the official gazette before
relying on it for real disclosure decisions.

## No personal data

- `sample/dokumen_fiksyen_mmkn.pdf` and everything under `output/` are
  generated by `scripts/make_sample_doc.py` and are **entirely fictional**:
  names, IC numbers, phone numbers, company names, bank accounts, and land
  titles are invented placeholders (e-mail addresses use the reserved
  `.example.my` domain). Any resemblance to real persons is coincidental.
- No real government documents, FOI requests, or applicant data are stored
  in this repo.
- `scripts/redact_demo.py` calls only a **locally-hosted LLM endpoint**
  (`http://aiserverstation:8080/...` — a LAN hostname, configurable). No
  data leaves the machine when you run the pipeline; there are no calls to
  third-party APIs.

## Reporting a vulnerability

Open a
[private security advisory](https://github.com/mohdhafizi83/foia-my-rules/security/advisories/new)
if you find a security issue (e.g. a script that sends data somewhere it
should not, or unexpected personal data committed by mistake).
